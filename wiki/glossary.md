# Glossary

One line each. Follow the link to the page with the full explanation.

- **API (Application Programming Interface)** — a defined way for one program to ask another program to do something or hand over data. [→ REST APIs](./02-rest-apis.md)
- **REST** — a common style of API where you interact with "resources" (like `/exams`) using standard HTTP verbs (GET, POST, etc). [→ REST APIs](./02-rest-apis.md)
- **HTTP** — the protocol (agreed-upon message format) browsers and servers use to talk to each other. [→ How the web works](./01-how-the-web-works.md)
- **Endpoint** — one specific URL + verb combination an API responds to, e.g. `POST /exams`. [→ REST APIs](./02-rest-apis.md)
- **Client / server** — the client asks (browser, app); the server answers (backend). [→ How the web works](./01-how-the-web-works.md)
- **Request / response** — the message the client sends, and the message the server sends back. [→ How the web works](./01-how-the-web-works.md)
- **Status code** — a 3-digit number in a response telling you broadly what happened (200 ok, 404 not found, 500 server broke). [→ REST APIs](./02-rest-apis.md)
- **JSON** — a text format for structuring data (nested key/value pairs) that both browsers and servers can read. [→ REST APIs](./02-rest-apis.md)
- **Database** — a system for storing data so it survives after your program stops running, and can be searched/updated reliably. [→ Databases & Firestore](./03-databases-and-firestore.md)
- **NoSQL / document database** — a database that stores flexible, nested "documents" (like JSON objects) instead of fixed-column tables. Firestore is one. [→ Databases & Firestore](./03-databases-and-firestore.md)
- **Collection** — Firestore's equivalent of a table: a named group of documents. [→ Databases & Firestore](./03-databases-and-firestore.md)
- **Document** — one record inside a collection, identified by an ID. [→ Databases & Firestore](./03-databases-and-firestore.md)
- **Denormalization** — deliberately duplicating a piece of data in more than one place so reads are simpler/faster, instead of always looking it up fresh. [→ Databases & Firestore](./03-databases-and-firestore.md)
- **Authentication (auth)** — proving who you are (logging in). [→ Auth & roles](./04-auth-and-roles.md)
- **Authorization** — once you know who someone is, deciding what they're allowed to do. [→ Auth & roles](./04-auth-and-roles.md)
- **Token** — a signed piece of data proving "this request really came from a logged-in user," sent with every API call. [→ Auth & roles](./04-auth-and-roles.md)
- **Role** — a label (like `teacher` or `student`) attached to a user that authorization checks are based on. [→ Auth & roles](./04-auth-and-roles.md)
- **Container** — a lightweight, self-contained bundle of an app + everything it needs to run, isolated from your actual machine. [→ Docker & local dev](./05-docker-and-local-dev.md)
- **Docker** — the tool used to build and run containers. [→ Docker & local dev](./05-docker-and-local-dev.md)
- **Emulator** — software that pretends to be a real cloud service, running locally, so you can develop without touching production. [→ Docker & local dev](./05-docker-and-local-dev.md)
- **Queue / job** — a to-do list of work items a background process works through one at a time (or a few at a time), instead of making the user wait. [→ Async jobs & queues](./06-async-jobs-and-queues.md)
- **Async(hronous)** — "doesn't block" — the request returns immediately and the actual work finishes later, separately. [→ Async jobs & queues](./06-async-jobs-and-queues.md)
- **Retry / dead-letter** — trying a failed job again automatically; after too many failures, giving up and flagging it for a human. [→ Async jobs & queues](./06-async-jobs-and-queues.md)
- **Component** — a reusable, self-contained piece of UI (a button, a card, a whole page) in React. [→ Frontend basics](./07-frontend-basics.md)
- **State** — data a component remembers and re-renders itself when it changes. [→ Frontend basics](./07-frontend-basics.md)
- **Props** — data passed into a component from its parent. [→ Frontend basics](./07-frontend-basics.md)
- **Routing** — mapping a URL path (like `/subjects/123`) to which screen/component renders. [→ Frontend basics](./07-frontend-basics.md)
- **Design token** — a named value (a color, a spacing size, a font size) used instead of a hardcoded number, so the whole app stays visually consistent. [→ Design systems & tokens](./08-design-systems-and-tokens.md)
- **Environment (dev/prod)** — a separate, isolated copy of the whole system (its own database, its own deployed backend) used for testing vs. real users. [→ Deployment & environments](./09-deployment-environments.md)
- **Deploy** — publishing a new version of the app so it's actually running somewhere reachable, instead of just on your laptop. [→ Deployment & environments](./09-deployment-environments.md)
